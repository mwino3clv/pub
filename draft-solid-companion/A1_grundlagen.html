Appendix A — Java-Grundlagen

NoteLernziele

Nach diesem Anhang kannst du …

  • erklären, was eine Klasse ist und wie ein Objekt daraus entsteht.
  • Attribute und Methoden einer Klasse benennen und unterscheiden.
  • einen Konstruktor schreiben und erklären, wozu er dient.
  • den Unterschied zwischen private und public beschreiben.
  • Getter und Setter implementieren und ihren Zweck erklären.
  • ein Interface definieren und von einer Implementierungsklasse unterscheiden.
  • das Interface ProductDao als Beispiel für einen Vertrag zwischen Klassen erklären.
  • eine ArrayList erstellen und mit einfachen Methoden nutzen.
  • das Dateiformat id;name;price beschreiben und einfache I/O-Operationen benennen.
  • die Begriffe SQL, JDBC und MariaDB erklären und ihren Zusammenhang beschreiben.

Dieser Anhang wiederholt die Java-Grundlagen, die für die Kapitel über N-Tier, SOLID und DAO wichtig sind. Er eignet sich als Nachschlagewerk — beim Lesen der Hauptkapitel kannst du jederzeit hier nachsehen.

A.1 Klassen und Objekte

Eine Klasse ist ein Bauplan für Objekte. Sie legt fest, welche Daten ein Objekt speichert und was es tun kann.

Ein Objekt ist eine konkrete Instanz dieses Bauplans. Mehrere Objekte können nach derselben Klasse erstellt werden — jedes mit eigenen Werten.

Das Alltagsbeispiel: Die Klasse ist die Bauzeichnung eines Hauses. Das Objekt ist das konkrete Haus, das nach dieser Zeichnung gebaut wurde.

Im weiteren Verlauf verwenden wir durchgehend die Klasse Product:

public class Product {
    private int id;
    private String name;
    private double price;
}

Product steht für ein Produkt in einem einfachen Warensystem. Die drei Attribute id, name und price beschreiben jeden Datensatz.

A.2 Attribute und Methoden

Eine Klasse besteht aus zwei Arten von Elementen.

Attribute beschreiben den Zustand eines Objekts. Sie speichern die Daten. Beispiel: id, name, price.

Methoden beschreiben das Verhalten eines Objekts. Sie führen Aktionen aus oder geben Werte zurück.

public class Product {
    // Attribute
    private int id;
    private String name;
    private double price;

    // Methode
    public void printInfo() {
        System.out.println(name + ": " + price);
    }
}

printInfo() gibt den Namen und den Preis des Produkts auf dem Bildschirm aus. Sie gehört zur Klasse Product und kann auf alle Attribute direkt zugreifen.

A.3 Konstruktoren

Ein Konstruktor ist eine spezielle Methode. Er wird automatisch aufgerufen, wenn ein Objekt mit new erstellt wird. Seine Aufgabe: die Startwerte der Attribute setzen.

public class Product {
    private int id;
    private String name;
    private double price;

    public Product(int id, String name, double price) {
        this.id    = id;
        this.name  = name;
        this.price = price;
    }
}

this.name = name unterscheidet das Attribut der Klasse (this.name) vom Parameter des Konstruktors (name). Ohne this wäre unklar, welche Variable gemeint ist.

Verwendung:

Product laptop = new Product(1, "Laptop", 999.99);
Product maus   = new Product(2, "Maus",    19.99);

laptop und maus sind zwei separate Objekte mit eigenen Werten.

A.4 Sichtbarkeit: private und public

Java regelt den Zugriff auf Klassen-Mitglieder mit Sichtbarkeits-Schlüsselwörtern.

Schlüsselwort Bedeutung
private Nur innerhalb der eigenen Klasse sichtbar
public Von überall sichtbar

Faustregel: Attribute sind private. Methoden sind meist public.

public class Product {
    private double price;    // nur intern zugänglich

    public double getPrice() {    // von außen aufrufbar
        return price;
    }
}

private schützt den internen Zustand des Objekts vor unkontrolliertem Zugriff von außen. Das ist ein Kernprinzip der Kapselung — englisch Encapsulation.

Andere Klassen können price nicht direkt lesen oder setzen. Sie müssen den kontrollierten Weg über getPrice() nehmen.

A.5 Getter und Setter

Da Attribute private sind, brauchen wir Methoden, um von außen auf sie zuzugreifen.

Getter geben den Wert eines Attributs zurück. Setter setzen einen neuen Wert.

public class Product {
    private String name;

    // Getter: Wert lesen
    public String getName() {
        return name;
    }

    // Setter: Wert setzen
    public void setName(String name) {
        this.name = name;
    }
}

Getter und Setter sind der kontrollierte Zugangspunkt zu privaten Attributen. Das klingt nach Schreibarbeit — und das ist es auch. In der Praxis werden sie deshalb meist automatisch generiert. In IntelliJ IDEA: Alt+Einfg → Getter and Setter.

Der eigentliche Vorteil: Ein Setter kann den neuen Wert prüfen, bevor er ihn übernimmt.

Erweitertes Beispiel:

public class Product {
    private int id;
    private String name;
    private double price;

    public Product(int id, String name, double price) {
        this.id    = id;
        this.name  = name;
        this.price = price;
    }

    public int    getId()    { return id;    }
    public String getName()  { return name;  }
    public double getPrice() { return price; }

    public void setName(String name) {
        if (name != null && !name.isEmpty()) {
            this.name = name;
        }
    }

    public void setPrice(double price) {
        if (price >= 0) {
            this.price = price;
        }
    }
}

setName() übernimmt den neuen Namen nur, wenn er nicht leer ist. setPrice() akzeptiert nur nicht-negative Preise. So bleibt das Objekt immer in einem gültigen Zustand.

A.6 Interfaces

Ein Interface legt fest, welche Methoden eine Klasse bereitstellen muss — ohne zu sagen, wie sie das tut. Es ist ein Vertrag. Die implementierende Klasse unterschreibt diesen Vertrag: „Ich garantiere, dass ich diese Methoden habe.”

Wie die Methoden intern funktionieren, ist Sache der Klasse — nicht des Interface.

public interface ProductDao {
    List<Product> findAll();
    Product findById(int id);
    void save(Product product);
    void deleteById(int id);
}

Dieses Interface legt vier Methoden fest. Jede Klasse, die ProductDao implementiert, muss alle vier bereitstellen.

Der Rest des Programms kann sich darauf verlassen — ohne zu wissen, wie die Methoden intern funktionieren. Das ist der Kern des DAO-Patterns (siehe ?sec-dao-pattern).

A.7 Interfaces implementieren

Das Schlüsselwort implements verbindet eine Klasse mit einem Interface.

public class InMemoryProductDao implements ProductDao {

    private List<Product> products = new ArrayList<>();

    @Override
    public List<Product> findAll() {
        return products;
    }

    @Override
    public void save(Product product) {
        products.add(product);
    }

    // findById und deleteById müssen ebenfalls implementiert werden
}

implements ProductDao bedeutet: Diese Klasse verpflichtet sich, alle Methoden des Interface bereitzustellen.

@Override ist technisch optional, aber empfohlen. Es macht sichtbar, dass hier eine Interface-Methode implementiert wird. Wenn der Methodenname falsch geschrieben ist, meldet der Compiler sofort einen Fehler.

Wenn eine Methode des Interface fehlt, gibt der Compiler einen Fehler. Das Interface erzwingt die Vollständigkeit — das ist sein Zweck.

Erweitertes Beispiel — alle vier Methoden:

public class InMemoryProductDao implements ProductDao {

    private List<Product> products = new ArrayList<>();

    @Override
    public List<Product> findAll() {
        return products;
    }

    @Override
    public Product findById(int id) {
        for (Product p : products) {
            if (p.getId() == id) return p;
        }
        return null;
    }

    @Override
    public void save(Product product) {
        products.add(product);
    }

    @Override
    public void deleteById(int id) {
        products.removeIf(p -> p.getId() == id);
    }
}

A.8 Interface als Variablentyp

Ein Interface kann als Typ für Variablen verwendet werden.

ProductDao dao = new InMemoryProductDao();

Die Variable dao hat den Typ ProductDao — das Interface. Das Objekt dahinter ist ein InMemoryProductDao.

Das ist der entscheidende Vorteil: Der Rest des Programms arbeitet mit dem Typ ProductDao, nicht mit InMemoryProductDao.

// Später einfach austauschen:
ProductDao dao = new TextFileProductDao();
// Kein anderer Code muss geändert werden.

Das nennt man Polymorphismus: Eine Variable eines Interface-Typs kann jede beliebige Implementierung halten. Der aufrufende Code merkt davon nichts — er ruft immer dieselben Methoden auf.

A.9 Collections: List und ArrayList

List ist ein Interface in Java für geordnete Listen. ArrayList ist die häufigste Implementierung — dynamisch wachsend, im Arbeitsspeicher.

List<Product> products = new ArrayList<>();

// Element hinzufügen
products.add(new Product(1, "Laptop", 999.99));

// Alle Elemente durchlaufen
for (Product p : products) {
    System.out.println(p.getName());
}

// Anzahl der Elemente
int anzahl = products.size();

List<Product> bedeutet: eine Liste, die ausschließlich Product-Objekte enthält. Die spitzen Klammern sind Generics — sie legen den Typ der enthaltenen Elemente zur Compilezeit fest. Wenn du versehentlich ein String-Objekt in eine List<Product> einfügen willst, meldet der Compiler sofort einen Fehler.

Erweitertes Beispiel — häufige Methoden:

List<Product> products = new ArrayList<>();

products.add(new Product(1, "Laptop", 999.99));
products.add(new Product(2, "Maus",    19.99));
products.add(new Product(3, "Kabel",    4.99));

// Größe prüfen
System.out.println("Anzahl: " + products.size());  // 3

// Element per Index lesen
Product erstes = products.get(0);   // Laptop

// Element entfernen (mit Lambda)
products.removeIf(p -> p.getId() == 2);  // Maus entfernen

// Prüfen ob leer
if (products.isEmpty()) {
    System.out.println("Keine Produkte vorhanden.");
}

A.10 Packages und Ordnerstruktur

Packages organisieren Klassen in Gruppen — ähnlich wie Ordner im Dateisystem. Klassen mit verwandten Aufgaben kommen in dasselbe Package.

src/
  main/
    java/
      dao/
        ProductDao.java
        InMemoryProductDao.java
        TextFileProductDao.java
        MariaDbProductDao.java
      model/
        Product.java
      service/
        ProductService.java
      view/
        ProductView.java

Package-Namen entsprechen den Ordnernamen. InMemoryProductDao.java liegt im Ordner dao/ — das Package heißt entsprechend dao.

In den Codebeispielen dieses Begleithefts werden package-Zeilen weggelassen, um die Übersichtlichkeit zu wahren. Im realen Projekt stehen sie am Anfang jeder Datei:

package dao;

public class InMemoryProductDao implements ProductDao {
    // ...
}

A.11 Datei-I/O: Lesen

Java kann Textdateien lesen und schreiben. Die Klassen BufferedReader und FileReader aus dem Paket java.io sind die Standard-Werkzeuge.

Das Dateiformat in diesem Projekt:

1;Laptop;999.99
2;Maus;19.99
3;Kabel;4.99

Jede Zeile enthält einen Datensatz. Die drei Felder id, name und price sind durch Semikolon getrennt.

BufferedReader reader = new BufferedReader(new FileReader("products.txt"));
String line;
while ((line = reader.readLine()) != null) {
    String[] parts = line.split(";");
    int    id    = Integer.parseInt(parts[0]);
    String name  = parts[1];
    double price = Double.parseDouble(parts[2]);
    // Product-Objekt erzeugen und zur Liste hinzufügen
}
reader.close();

split(";") zerlegt eine Zeile an jedem Semikolon. Das Ergebnis ist ein Array: parts[0] enthält id, parts[1] enthält name, parts[2] enthält price.

NoteHinweis

Die Fehlerbehandlung (try-catch, IOException) ist in diesem Beispiel weggelassen. Im realen Code muss sie ergänzt werden.

A.12 Datei-I/O: Schreiben

Zum Schreiben verwenden wir BufferedWriter und FileWriter:

BufferedWriter writer = new BufferedWriter(new FileWriter("products.txt"));
for (Product p : products) {
    writer.write(p.getId() + ";" + p.getName() + ";" + p.getPrice());
    writer.newLine();
}
writer.close();

FileWriter öffnet die Datei zum Schreiben. newLine() fügt nach jeder Zeile einen Zeilenumbruch ein.

writer.close() am Ende ist wichtig. Ohne close() werden die Daten möglicherweise nicht vollständig in die Datei geschrieben, weil sie noch im Puffer liegen.

Erweitertes Beispiel mit Fehlerbehandlung:

try (BufferedWriter writer =
         new BufferedWriter(new FileWriter("products.txt"))) {
    for (Product p : products) {
        writer.write(p.getId() + ";" + p.getName() + ";" + p.getPrice());
        writer.newLine();
    }
} catch (IOException e) {
    System.err.println("Fehler beim Schreiben: " + e.getMessage());
}

Das try-with-resources-Konstrukt schließt den Writer automatisch — auch wenn ein Fehler auftritt.

A.13 Datenbanken: Grundbegriffe

Datenbanken speichern Daten dauerhaft und strukturiert. Drei Begriffe sind für dieses Begleitheft wichtig.

Begriff Bedeutung
Tabelle Struktur zum Speichern gleichartiger Daten — ähnlich wie eine Tabellenkalkulation
Zeile Ein einzelner Datensatz, z. B. ein Produkt
Spalte Ein Datenfeld, z. B. name oder price
SQL Structured Query Language — die Sprache für Datenbankabfragen
JDBC Java Database Connectivity — die Standard-API, über die Java mit Datenbanken kommuniziert
MariaDB Ein relationales Datenbanksystem — Open Source, kompatibel mit MySQL

Relationale Datenbank bedeutet: Daten werden in Tabellen gespeichert. Tabellen können über gemeinsame Felder verknüpft werden.

A.14 Die Tabelle product in MariaDB

In MariaDB wird die Tabelle product so angelegt:

CREATE TABLE product (
    id    INT PRIMARY KEY AUTO_INCREMENT,
    name  VARCHAR(100),
    price DOUBLE
);

AUTO_INCREMENT bedeutet: MariaDB vergibt die id automatisch. PRIMARY KEY bedeutet: Jede Zeile hat eine eindeutige id. VARCHAR(100) ist eine Zeichenkette mit maximal 100 Zeichen.

Einfache SQL-Abfragen:

-- Alle Produkte lesen
SELECT id, name, price FROM product;

-- Neues Produkt einfügen
INSERT INTO product (name, price) VALUES ('Laptop', 999.99);

-- Produkt mit id=2 löschen
DELETE FROM product WHERE id = 2;

Jede SQL-Abfrage hat eine feste Struktur: SELECT liest Daten, INSERT fügt Daten ein, DELETE löscht Daten.

A.15 JDBC: Grundidee

JDBC (Java Database Connectivity) ist die Standard-Schnittstelle, über die Java-Programme mit Datenbanken kommunizieren.

// Verbindung öffnen
Connection con = DriverManager.getConnection(
    "jdbc:mariadb://localhost:3306/meinedb", "user", "passwort"
);

// Abfrage vorbereiten und ausführen
PreparedStatement stmt = con.prepareStatement(
    "SELECT id, name, price FROM product"
);
ResultSet rs = stmt.executeQuery();

// Ergebnis zeilenweise lesen
while (rs.next()) {
    int    id    = rs.getInt("id");
    String name  = rs.getString("name");
    double price = rs.getDouble("price");
    // Product-Objekt erzeugen ...
}

Voraussetzung: Der MariaDB Connector/J muss als JAR-Datei im Projekt eingebunden sein. JDBC ist Teil von Java — der Connector ist die Brücke zu MariaDB. Ohne diese JAR-Datei kann Java nicht mit MariaDB kommunizieren.

NoteHinweis

Dieses Beispiel ist bewusst vereinfacht — Fehlerbehandlung und close()-Aufrufe fehlen. Im realen Code müssen sie ergänzt werden.

A.16 Alles zusammen

Alle Konzepte aus diesem Anhang greifen ineinander.

Das Interface ProductDao legt den Vertrag fest. InMemoryProductDao implementiert diesen Vertrag. Es speichert Product-Objekte in einer ArrayList.

ProductService hängt vom Interface ab — nicht von der Implementierung. Damit bleibt ProductService unverändert, wenn die Implementierung wechselt.

// Interface definiert den Vertrag
public interface ProductDao {
    List<Product> findAll();
    void save(Product product);
}

// Implementierung erfüllt den Vertrag
public class InMemoryProductDao implements ProductDao {
    private List<Product> products = new ArrayList<>();

    @Override
    public List<Product> findAll() { return products; }

    @Override
    public void save(Product product) { products.add(product); }
}

// Service hängt vom Interface ab — nicht von der Implementierung
public class ProductService {
    private ProductDao dao;

    public ProductService(ProductDao dao) { this.dao = dao; }

    public List<Product> getAll() { return dao.findAll(); }
}

Verwendung:

ProductDao dao       = new InMemoryProductDao();
ProductService svc   = new ProductService(dao);
List<Product> liste  = svc.getAll();

Wird später eine andere DAO-Variante benötigt, ändert sich nur die erste Zeile. ProductService und alle anderen Klassen bleiben unberührt.

A.17 Merksätze

Klasse und Objekt: Eine Klasse ist ein Bauplan. Ein Objekt ist eine konkrete Instanz dieses Bauplans.

private / public: Attribute sind private. Methoden regeln den kontrollierten Zugang.

Konstruktor: Der Konstruktor setzt beim Erstellen eines Objekts die Startwerte der Attribute.

Interface: Ein Interface ist ein Vertrag. Wer ihn mit implements übernimmt, muss alle Methoden bereitstellen.

Polymorphismus: Eine Variable vom Typ eines Interface kann jede beliebige Implementierung halten.

List / ArrayList: List<Product> ist eine typsichere Liste von Product-Objekten. ArrayList ist die einfachste Implementierung.

JDBC: Java kommuniziert über JDBC mit Datenbanken. Der MariaDB Connector/J ist die Bibliothek, die das für MariaDB ermöglicht.
